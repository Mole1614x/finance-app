# PR 7 — Transaction history and receipts
GET /api/v1/transactions lists committed ledger entries for the authenticated user, including opening funds, internal moves, sent payments and received payments. Filters: kind, since/until (inclusive Unix seconds), limit and offset. Stable ordering uses timestamp and journal ID; offset pages may shift if new entries arrive. GET /api/v1/transactions/{transaction_id} returns a participant-scoped receipt with UTC timestamp, references and amount in integer paise. Internal moves do not change the combined user balance. No other user's identity or account details are exposed. Dashboard lists the latest five entries; chart is still illustrative.

POST /api/v1/transactions/payment-lookup accepts an idempotency key and returns completed only for the sender's committed payment, otherwise unknown. It is read-only: unknown is not proof of failure or authorization to repeat using another key. Reuse the original key for an interrupted request. No asynchronous pending/failed ledger rows are fabricated; failed transactions roll back. Durable pending recovery across app restarts and independent payment-provider reconciliation remain future work.

Mobile history supports type filter, paging, receipt viewing/copying, and in-session payment status lookup. Date filtering is API-only. Device UI, original Figma assets, PostgreSQL runtime and production migrations remain unverified. No real money, banking or UPI.
