# PR 14 — Local QR decoding and durable peer payment recovery

The native Scan screen opens a Kivy camera preview only on explicit request (Android runtime permission is requested). OpenCV decodes frames locally. No frames are sent to a backend or retained. Only exact ARTH demo identifiers are accepted; a detected code fills the input, and the user must choose Use QR identifier, review and confirm. Camera stops on exit, pause or explicit stop. Manual identifier entry remains available. CI tests generated QR images and screen construction, not a physical camera. Android OpenCV recipe and camera permissions need actual APK/device verification.

Peer sends store one pending request per backend URL and authenticated user ID in the app-private SQLite directory, with a restrictive file mode on supported platforms. The store commits before the network send, contains the demo recipient, integer paise and original UUID key only, and survives restart/re-login. No passwords or access tokens are persisted. On Send entry the app checks pending records with the authenticated profile. No automatic transfer occurs. Retry uses the original key; check status is read-only. A corrupted/unavailable store prevents new sends. The backend's cancel endpoint serializes with send via the owner lock: if already committed, returns the receipt; otherwise writes a durable cancellation tombstone which rejects delayed/replayed sends. The app clears local storage only on a confirmed completed or cancelled response. This is not a refund or reversal. A local storage deletion or app uninstall can lose an unresolved reference.

POST /api/v1/payments/recover and /cancel accept an idempotency_key. Unknown is not proof of failure. Alembic revision 0002 adds cancellation tombstones; upgrade before managed deployment. Never downgrade or delete the table in a database with cancelled requests, because that removes replay protection. For existing pre-Alembic databases follow baseline adoption instructions. Existing in-memory service purchase and savings-move recovery are not upgraded in this PR. No real UPI, financial credentials or production secure device storage. Device camera, APK and Figma parity remain outstanding.
