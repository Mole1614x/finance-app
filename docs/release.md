# PR 10 — Local demo release readiness (0.9.0)

ARTH is a simulated finance application, not a regulated payment product. Do not expose it publicly. Fresh Docker start: python3 scripts/init_demo_env.py, then docker compose up --build -d. The generated .env is private and ignored. The API is loopback-only; migration completes before API and worker start. PostgreSQL and Redis are internal. Do not commit .env, use real banking data or reuse these demo credentials in production.

Local non-Docker development retains SQLite automatic table creation and ephemeral signing secret unless configured. For managed mode, set DATABASE_URL and a strong ARTH_JWT_SECRET, run alembic upgrade head, then set ARTH_MANAGED_SCHEMA=1 for the API. Existing pre-PR10 databases already have tables but no Alembic revision; do not run baseline upgrade blindly. Back up, compare schema to the frozen baseline, and only after confirming equivalence use alembic stamp 0001_demo_baseline. Never downgrade a populated database without a backup; baseline downgrade deletes its tables. Old Compose volumes may retain the previous local password; retain the old password in private configuration for migration or intentionally create a new disposable volume after backup. No automatic destructive reset.

Rate limiting is per direct peer IP and route group with a 60-second fixed window; configured Redis provides cross-process counters and fail-closed behavior. Local fallback is bounded in-memory and is not suitable for a public or distributed service. Proxy headers disabled in Compose. Sensitive API responses use no-store. The demo OTP is intentionally not real identity verification. No public deployment, security audit or regulatory compliance claim.

CI tests SQLite, a disposable PostgreSQL database, Redis counters, Celery ping and local Compose startup. The PostgreSQL test suite drops tables only in explicitly configured arth_test; never point it at a real database. Kubernetes manifests are local-cluster examples and must not be exposed to the Internet. Android build configuration updated but APK, iOS, physical-device testing, exact Figma assets, live QR camera scanning, durable mobile payment recovery, secure device token storage, real OTP/payment integrations, trained ML and LLM remain outstanding. Journal mutation restrictions at the database level remain future work. Release is a demo, not production-ready.
