# PR 8 — Demo utility services and cashback
All providers, bills, plans and prices are fictional. There is no external provider, actual mobile recharge, customer account, or real payment. Each utility has one fictional bill per UTC calendar month with an illustrative due date on the 28th; recharge plans can be purchased repeatedly. The catalog shows paid status and due dates in-app, not scheduled reminders or push notifications. Server fixes the purchase amount. Demo cashback is 2% capped at INR 20 per purchase, credited directly to checking; lifetime earned is an informational total, not an independently spendable balance.

The existing per-owner funding counter-account serves as simulated clearing for charges and cashback. Both journal pairs and the service order commit atomically under the owner lock. A failed charge cannot earn cashback. Same request key returns original order; a conflicting key or repeat bill is rejected. Existing ledger schema is preserved; service and reward journal entries have distinct key namespaces and history categories. No real-money integration.

API: GET /api/v1/services/catalog, POST /purchase with Idempotency-Key, GET /orders (paged), GET /rewards. Mobile shows catalog, review/confirmation, latest orders and lifetime rewards. Retry uses same in-memory key; recovery after restart remains pending. Scheduled reminders, mobile device tests, PostgreSQL runtime, migrations and exact Figma assets remain unverified or unimplemented.
