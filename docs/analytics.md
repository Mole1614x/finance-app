# PR 9 — Demo financial analytics and planning
Reports are calculated from committed, owner-scoped ledger transactions using UTC calendar months. Opening demo funds are separate from received payments and cashback. Internal account moves do not count as expenses or income. Spending categories come from the service catalog and peer transfers. The home chart now uses daily net ledger changes instead of illustrative numbers; the old cashflow field remains a compatibility alias.

Budgets are one total spending limit per user and month; savings goals are one target linked to the actual demo savings balance, not earmarked funds. Updates are owner-scoped. A linear spending projection is available after seven completed days, excluding the partial current day; it is not a trained predictive model. A transparent heuristic flags expenses of at least INR 1,000 and three times the median of at least four preceding same-month expenses, for review only. No fraud classification or validated risk score is claimed.

The assistant is a local, topic-based deterministic interface for spending, budget, savings and risk summaries. No LLM, Gemini, LangGraph, ML model training, external data transmission or real financial advice. A trained fraud model needs appropriate labeled data and evaluation. No live banking or real money.

API: GET /api/v1/analytics/summary?month=YYYY-MM, PUT /budget, GET/PUT /goal, POST /assistant. Mobile provides reports, budgets, one savings goal and an in-session idempotent savings move; persistent recovery and secure storage still pending. Mobile amount entry currently has the existing INR 10 lakh cap, lower than the API budget/goal maximum. SQLite CI covers calculations and isolation; PostgreSQL, device UI and exact Figma verification remain pending.
