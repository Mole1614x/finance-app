# PR 13 — Synthetic ML anomaly review
Isolation Forest (96 trees, 256 maximum training samples per tree, 5% contamination, seed 1701) fits 2,400 normal synthetic feature vectors lazily per backend process; no downloaded model, pickle or customer training data. Features: log2 amount relative to the rolling median of up to 30 preceding outgoing expenses, log1p absolute rupee amount and the count of preceding expenses within one hour (capped at 100 for model input). Four strictly earlier expenses are required. Same-second entries are scored against the same earlier history; their intra-second order is unknown. Features are generated separately for each authenticated owner's selected UTC month. Internal transfers, incoming funds, opening balances and cashback are excluded. The previous rule-based flags remain separate.

Run python -m scripts.evaluate_anomaly_model for deterministic held-out synthetic evaluation (seed 2701, 900 normal and 150 injected unusually large/burst/combined examples). Outputs precision, recall, F1, ROC-AUC and confusion matrix. These labels are generator-defined, not fraud labels; metrics demonstrate only behavior on the chosen simulated distributions and cannot establish real-world performance. No claim of a calibrated probability. Dependency versions are bounded but not fully locked, so exact metrics may vary across versions. A positive inverted decision-function score yields a review flag. Displayed ratio and count are descriptive context, not causal feature attributions. Latest ten flagged entries are returned, along with total count. An insufficient-history status is not evidence of safety.

GET /api/v1/analytics/risk?month=YYYY-MM is authenticated, read-only, owner-scoped; no model call on ordinary dashboard/summary. Risk assistant adds local ML results, while Gemini continues receiving only the original aggregate rule-flag count (no transaction IDs, ML scores or individual records). Mobile has a separate review screen. No automatic payment blocking, real money, sanctions, or actual fraud classification. Live device testing remains pending. Real-world fraud detection would require representative consented labeled data, calibration, drift monitoring, fairness review, independent validation and human oversight.
