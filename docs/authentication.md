# PR 3: demo authentication

Run the backend before the mobile client. Register a fictional address such as demo@example.com and a demo password of at least eight characters, then enter fictional mobile number 9000000000. A server-generated four-digit demo code is displayed in the app; no SMS or ownership verification occurs. Sign in again with the same credentials later. Do not use real credentials.

SQLite is the local default (arth-demo.db ignored by git); Compose sets DATABASE_URL to PostgreSQL. Schema is created on first use for development. Alembic migrations, production secrets, distributed rate limits, real OTP provider, verified phone ownership, device binding, password reset, recovery, and secure mobile token storage remain future work. JWT signing secret is random per process by default; set ARTH_JWT_SECRET to a long random secret in the environment for consistent development sessions. Do not expose the demo backend to public networks. Tokens are in-memory only on mobile. Refresh is supported by the API; automatic mobile refresh and profile editing UI are pending. Android emulator API URL can be configured via ARTH_API_URL=http://10.0.2.2:8000; packaging/networking not tested. Existing demo dashboard remains public synthetic data only. No actual money.
